01

Dữ liệu giả lập & Variance Engine

04–07/10

Vì sao phải làm trước tiên: toàn bộ thí nghiệm cần một "đề thi có đáp án". Phase này tạo ra đề thi đó: số liệu giả lập giống cấu trúc file thật, mỗi chênh lệch được GIEO một nguyên nhân biết trước (gold label) — nhờ vậy sau này chấm điểm AI được bằng máy.

1a · Kịch bản gieo — file scenarios.yaml trông thế nào

# Mỗi kịch bản = một loại nguyên nhân có thật ngoài đời (rút từ comments T1–T8)
- id: early_termination          # tenant chấm dứt sớm
  side: revenue
  effect: "actual rent = 0 từ tháng hiệu lực; budget vẫn giả định thuê tiếp"
  evidence_sinh_kem: termination_notice   # cấp 1 — bằng chứng mạnh
  gold_cause: early_termination
- id: handover_delay             # lease mới dời ngày bàn giao
- id: rent_escalation            # đơn giá tăng theo hợp đồng
- id: one_off_repair             # chi phí sửa chữa đột xuất
- id: missing_evidence           # BẪY: không sinh bằng chứng → hệ thống phải TỪ CHỐI
- id: keyword_trap               # BẪY: tài liệu trùng từ khóa nhưng sai property

1b · Dữ liệu sinh ra — bảng GL giả lập (trích)

5 property × 12 tháng × ~10 PL line → vài nghìn dòng GL, ~25 case trọng yếu được gieo.

1c · Đáp án gắn kèm — gold_labels.json trông thế nào

{
  "case_id": "2026-07_PROP-C_511",
  "gold_cause": ["early_termination", "handover_delay"],
  "gold_evidence": ["EV-112", "EV-128"],
  "facts": { "variance": -85000, "ten_014_delta": -60000, "ten_027_delta": -32000 },
  "prohibited_claims": ["thị trường chững lại", "giá vật liệu tăng"]  // AI nói câu này = bịa
}

1d · Rút từ comments thật T1–T8 — docs/house_style.md (ẩn danh)

Khung comment chuẩn nhà (ví dụ minh họa): 3–5 câu — (1) số liệu MTD/YTD so budget; (2) driver chính kèm số; (3) yếu tố bù đắp/timing; đơn vị nghìn; văn phong ngắn gọn.

early terminationhandover delayescalation FXone-off repairtimingreversal

Cause taxonomy thật sẽ rút từ 8 file PL_Act vs budget — chỉ mô tả ẩn danh, không chép nguyên văn.
